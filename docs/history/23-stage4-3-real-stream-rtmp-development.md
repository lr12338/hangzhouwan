# 阶段4.3 真实流RTMP推流开发报告

## 概述

本阶段实现单路 RTSP 实流 -> Sophon 硬件解码 -> BMCV 预处理 -> BMRuntime 推理 -> BMCV 绘框 -> h264_bm 硬件编码 -> FLV/RTMP 网络推流的完整链路，并对 A、B 两路真实流进行顺序短测验证。

公共文档中使用占位符 `STREAM_A_INPUT_URL`、`STREAM_A_OUTPUT_URL`、`STREAM_B_INPUT_URL`、`STREAM_B_OUTPUT_URL`，不记录真实地址。

## 关键性能优化

真实视频为 2560x1440（远大于测试视频 960x544），CPU 预处理路径耗时 331ms/帧，无法满足实时性。

优化：将 BMCV 预处理从"全分辨率 CSC -> D2H 11MB -> CPU sws resize"改为"BMCV VPP 一步完成 CSC+resize -> D2H 1.2MB"，预处理耗时从 188ms 降至 44ms。

## 分辨率处理

- 推理输入直接 resize 到 640x640（BMCV VPP 设备端完成）
- 输出保持原始视频分辨率 2560x1440
- BMCV 在原始 NV12 上绘框
- 禁区坐标以原始参考分辨率 2560x1440 定义
- 不使用 letterbox，不强制输出为 960x540
- 初始码率 800kbps 为测试起点

## 实现要点

### RTMP 网络输出

- `sink_type=file|rtmp`：CLI 选择本地文件或 RTMP 推流
- RTMP 使用 FLV muxer + `avio_open2`，不通过文件扩展名判断容器
- 设置 `rw_timeout` 为 10 秒写超时
- 部分 CDN 服务器在 publish 命令后需要处理时间，写头后延迟 500ms

### RTMP 重连状态机

- 退避序列：1s, 2s, 5s, 10s, 30s 封顶
- 重连步骤：停止旧 muxer -> 释放旧 encoder -> 关闭旧 IO -> 等待退避 -> 重建 encoder -> 重建 FLV muxer -> 重开 RTMP -> 重写 header
- RTMP 重连不重新连接 RTSP，不重新加载 bmodel
- 新 RTMP 会话重置 PTS（避免 non-monotonous DTS）
- 断线期间队列保持容量 1，只保留最新帧

### RTSP 时间调度

- RTSP 模式使用 `steady_clock` 墙钟时间调度，不依赖源帧率整除关系
- output interval = 1000 / output_fps（默认 100ms）
- inference interval = 1000 / inference_fps（默认 200ms）
- RTSP 重连后重置调度并清空 DetectionSnapshot
- 本地文件模式行为不变（基于序列号抽帧 + 源帧率回放节流）

### 禁区过滤

- 旧 Python 语义审计：框中心点包含关系，NMS 后绘框前过滤
- 矩形判断含边界，多边形使用射线法（半开边界）
- 坐标按实际分辨率比例换算
- 处理顺序：YOLO后处理 -> NMS -> 禁区过滤 -> 绘框
