# 船舶检测与跟踪系统 - 优化部署指南

## 📋 优化概述

本优化方案针对视频流延迟和卡顿问题，从以下几个方面进行了全面优化：

### 🎯 主要优化内容

1. **FFmpeg编码优化** - 低延迟编码参数配置
2. **Nginx RTMP优化** - 流媒体服务器性能调优
3. **Python代码优化** - 多线程架构重构
4. **系统级优化** - Windows系统参数调优
5. **自适应质量控制** - 根据系统负载动态调整

## 🔧 详细配置说明

### FFmpeg优化参数详解

| 参数 | 原值 | 优化值 | 说明 |
|------|------|--------|------|
| `-preset` | `veryfast` | `ultrafast`/`veryfast` | 根据负载自适应 |
| `-tune` | `zerolatency` | `zerolatency` | 零延迟调优 |
| `-crf` | `30` | `25-32` | 根据质量等级动态调整 |
| `-g` | `10` | `15` | GOP大小优化 |
| `-bufsize` | 未设置 | `1000k` | 缓冲区大小限制 |
| `-maxrate` | 未设置 | `2000k` | 最大比特率限制 |

### Nginx RTMP优化配置

```nginx
rtmp {
    server {
        listen 1935;
        chunk_size 4096;          # 优化块大小
        max_streams 32;           # 最大流数量
        ack_window 5000000;       # 确认窗口
        
        application HangZhouBridge {
            live on;
            interleave on;        # 交错模式
            wait_key on;          # 等待关键帧
            wait_video on;        # 等待视频
            sync 10ms;            # 同步优化
            
            # 低延迟HLS
            hls_fragment 2s;      # 2秒片段
            hls_playlist_length 6s; # 6秒播放列表
        }
    }
}
```

### Python代码架构优化

#### 原始架构问题
- 单线程处理读取和推流
- 帧缓存策略简单
- 缺少性能监控

#### 优化后架构
```python
# 三线程分离架构
1. 读取线程：专门负责从RTSP读取帧
2. 处理线程：专门负责检测和标注
3. 推流线程：专门负责FFmpeg推流

# 队列缓存机制
- 使用queue.Queue替代简单列表
- 限制队列大小避免内存积压
- 非阻塞操作防止线程卡死
```

## 🚨 常见问题解决

### 推流中断问题 (Broken Pipe)
**症状**: 日志显示 `[Errno 32] Broken pipe` 错误
**解决方案**:
```bash
# 1. 运行修复脚本
python fix_streaming_issues.py

# 2. 测试RTMP连接
python test_rtmp_connection.py

# 3. 检查Nginx服务状态
tasklist /FI "IMAGENAME eq nginx.exe"
```

### FFmpeg进程异常
**症状**: FFmpeg进程启动失败或异常退出
**解决方案**:
```bash
# 清理残留进程
taskkill /F /IM ffmpeg.exe

# 重新启动系统
python starter_optimized.py
```

### RTMP服务器连接失败
**症状**: 无法连接到RTMP推流地址
**解决方案**:
1. 检查网络连接
2. 验证RTMP服务器状态
3. 确认推流地址正确
4. 检查防火墙设置
